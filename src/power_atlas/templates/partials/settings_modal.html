General

How PowerAtlas starts and where it listens. Both are read at startup.

Agent permissions not in effect

What the ACP sessions PowerAtlas creates with Default may do without asking.

Permission mode
New sessions run every action without asking, except the Always blocked list, which is refused silently. kiro-cli itself still asks before writes to .git, .vscode, *.code-workspace, .kiro/agents and .kiro/hooks, and blocks writes to .kiroignore and .kiro/settings, in every mode.
The Always blocked list, plus your Manual rules (Edit rules… shows them): what a rule does not allow asks first, and file-tool writes to Protected items always ask.
Rules and agent
Manual rules
What runs without asking, what asks and what is blocked, per kind of action. The rules apply when Manual is selected.
The kiro-cli agent PowerAtlas builds its own agent from. It is read, never modified; if it is missing, a minimal agent is used instead.
Reference
Always blocked

Refused silently in every mode, in the ACP sessions PowerAtlas creates with Default. A session reopened from before the Always blocked list was in effect keeps the agent it started with, and is not covered.

Protected (Manual)

In Manual, file-tool writes to these always ask, even when writing files is allowed. A link inside one of these folders that points elsewhere is not covered, in a project's own .kiro folder too.

Changes apply to sessions created afterwards. A reopened session keeps the agent it started with, so it is outside the Always blocked list if PowerAtlas's agent was not in effect when it started. Terminal sessions and task modes such as Spec or Plan are not covered.

Browser sign-in

Browsers sign in with a login code PowerAtlas mints when it opens its own window or when the tray's Copy login link is used.

Sign out other browsers
Rotates the local sign-in key. Every other browser signed in to PowerAtlas must be reopened from the tray; this one stays signed in.
